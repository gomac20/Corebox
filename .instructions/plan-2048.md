# Plan 서브에이전트 지침 — 2048 게임

## 역할
2048 웹앱의 **계획만** 작성한다. 구현하지 않는다.

## 요청 배경
사용자 요청: "2048 게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘."

## 해야 할 일
1. `D:\OneDrive\Desktop\클로드실습\클로드코드\블로그만들기실습\CLAUDE.md`를 읽고 "웹앱 규칙"과 "작업 사이클"을 확인한다.
2. `index.html`, `css/`, `js/`를 읽어 기존 블로그의 구조와 카드 영역을 파악한다. (읽기만 한다.)
3. 아래 항목을 담은 계획을 `D:\OneDrive\Desktop\클로드실습\클로드코드\블로그만들기실습\spec.md`로 저장한다.

## spec.md에 반드시 포함할 내용
- **앱 개요**: 무엇을 만드는지 2~3줄
- **기능 목록**
  - 4×4 보드, 방향키(↑↓←→)로 타일 이동·합치기, 이동 후 새 타일(2 또는 4) 생성
  - 점수판: 현재 점수, 최고 점수(localStorage 저장, 접근 실패해도 동작)
  - 새 게임 버튼, 2048 달성 시 승리 표시, 이동 불가 시 게임 오버 표시
  - 모바일 지원: 스와이프 입력, 터치 대상 최소 44px, 가로 스크롤 없음
- **파일 구조**: `apps/2048/` 안에 들어갈 파일 목록과 각 파일의 역할 (자체 완결)
- **핵심 로직 설계**: 한 줄 밀기·합치기 알고리즘, 한 번 이동에서 같은 타일이 두 번 합쳐지지 않는 규칙, 이동이 일어났을 때만 새 타일 생성
- **화면 설계**: 레이아웃, 타일 숫자별 색상 방향, 반응형 기준 폭(375/768/1280)
- **Embed 계획**: `index.html`에 추가할 웹앱 카드(제목, 설명, 미리보기 방식)
- **Review 체크리스트**: 검증할 항목 목록
- **열린 질문**: 사용자 결정이 필요한 것 (없으면 "없음")

## 수정 범위 (엄수)
- 만들거나 수정해도 되는 파일: `spec.md` **하나뿐**.
- 그 외 모든 파일은 읽기만 한다. `apps/`, `index.html`, `css/`, `js/`, `CLAUDE.md`를 수정하지 않는다.
- 코드를 구현하지 않는다. 의사코드는 spec.md 안에서만 허용한다.
- 파일 삭제, git 명령 실행을 하지 않는다.

## 끝나면
작성한 spec.md의 핵심을 10줄 이내로 요약해 보고한다.
