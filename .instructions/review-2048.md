# Review 서브에이전트 지침 — 2048 게임

## 역할
Build 단계에서 만든 2048 웹앱을 **독립적으로 검증**한다. 구현자가 아니라 검증자의 시각으로 본다. Build 에이전트의 보고("잘 동작한다")를 믿지 말고 직접 확인한다.

## 입력
- 계획서: `D:\OneDrive\Desktop\클로드실습\클로드코드\블로그만들기실습\spec.md` (Review 체크리스트 포함)
- 대상: `D:\OneDrive\Desktop\클로드실습\클로드코드\블로그만들기실습\apps\2048\` (`index.html`, `style.css`, `game.js`, `app.js`)
- 규칙: 같은 폴더의 `CLAUDE.md` "웹앱 규칙"

## 검증 방법
1. 코드 리뷰: 4개 파일을 모두 읽고 버그, 예외 처리 누락, 규칙 위반을 찾는다.
2. 로직 테스트: `game.js`의 `slideLine`, `move` 등을 직접 호출해 spec.md 체크리스트의 합치기 케이스(`[2,2,2,2]`→`[4,4,0,0]`, `[2,2,4,0]`→`[4,4,0,0]`, `[4,0,4,8]`→`[8,8,0,0]`)와 네 방향 이동, 이동 불가 판정, 점수 증가량을 확인한다. (브라우저 콘솔 또는 Node가 없으면 브라우저에서 확인)
3. 브라우저 검증: 로컬 서버를 띄워 실제로 연다. `fetch`/ES module을 쓰므로 `file://`로는 안 된다. 예: `python -m http.server 8765`(블로그만들기실습 폴더에서) 후 `http://localhost:8765/apps/2048/index.html`.
   - 방향키 4방향 동작, 페이지 스크롤 방지
   - 새 타일 생성 규칙(변화 없는 이동에서는 생성 안 됨)
   - 점수판, 최고 점수 저장·복원, localStorage가 막혀도 오류 없음
   - 새 게임, 승리 오버레이("계속하기"), 게임 오버 오버레이
   - 375px / 768px / 1280px 폭에서 가로 스크롤 없음, 버튼 44px 이상
   - 콘솔 오류 없음, `apps/2048/` 밖 파일을 참조하지 않음
4. 검증이 끝나면 띄운 서버를 반드시 종료한다.

## 산출물
`D:\OneDrive\Desktop\클로드실습\클로드코드\블로그만들기실습\review.md`를 작성한다.
- spec.md 체크리스트 13항목 각각에 대해 **통과 / 실패 / 확인 못 함** 과 근거
- 발견한 문제 목록(심각도, 위치, 재현 방법)
- 수정한 내용
- 확인하지 못한 것(있다면 이유)

## 수정 범위 (엄수)
- 문제를 발견하면 `apps/2048/` 안의 4개 파일만 수정해도 된다. 수정은 발견한 문제를 고치는 최소 변경으로 한다. 기능 추가·디자인 변경은 하지 않는다.
- `review.md`를 생성·수정할 수 있다.
- 그 외 모든 파일은 수정하지 않는다. 특히 블로그 메인 `index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `spec.md`, `.claude/`, `.instructions/`를 건드리지 않는다.
- 파일 삭제, git 명령 실행을 하지 않는다. (임시 파일을 만들었다면 `apps/2048/`가 아닌 스크래치 위치에 두고 지우지 말고 보고에 적는다.)
- 수정했다면 수정 후 해당 항목을 다시 검증한다.

## 막히면
브라우저를 열 수 없는 등 검증이 불가능한 항목은 "확인 못 함"으로 솔직하게 적는다. 통과로 추정해 적지 않는다.

## 끝나면
통과/실패/확인 못 함 개수, 수정한 내용, 남은 문제를 10줄 이내로 보고한다.
